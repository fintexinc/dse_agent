# Auditoria de escala do DSE — síntese para decisão

## Diagnóstico

O que impede escalar não é falta de mecanismo: é que **a forma de cada repositório está escrita no código da plataforma**, e existe uma segunda plataforma inteira que nunca executa. O `.dse/validation.json` já é lido em todos os pontos onde a decisão é tomada — o Tester faz `cat` dele dentro do Pod doze linhas acima da escada `npm/mvnw/mvn/pytest` (`activities.py:2990-3013` vs `:3278-3314`), o preview lê `commands.build` pela API do GitHub antes de o Pod existir (`argocd.py:673`, `:1521`) e mesmo assim termina em `exec java -jar "$JAR"` literal (`argocd.py:466-467`) — mas em nenhum deles ele é a fonte de **como subir**, **como testar**, **em que imagem** e **com que dependências**. Cada ecossistema suportado até hoje entrou como um degrau de `elif`, nunca como uma declaração, e por isso o repo N+1 custa uma rc da plataforma. O efeito colateral é pior que o custo: os gates estão calibrados para o dialeto de dois testbeds, e fora de ruff/mypy/tsc/jest/pytest/surefire eles não reprovam — **passam** (lint e typecheck reproduzidos 4/4 devolvendo `PASS` com exit 1; SAST devolvendo PASS explícito em todo repo sem `.py` e também em OOM; o L2 julgando a string `"N turn(s) executed via ClaudeAgentSubstrate"`), de modo que o modo de falha de uma linguagem nova não é vermelho: é verde sem evidência, publicado no PR como "2 gates verdes". Em paralelo, ~5.200 das 101.000 linhas Python de `services/`+`packages/` são mecanismo construído e nunca ligado — retrieval, fix_loop, tenant_isolation, evidence/Garage+Playwright, o driver Docker, os dois modos de preview que são o **default do chart**, e o revisor L2 real registrado no worker e jamais invocado (`grep 'wse_' services/orchestrator/src/` = 0 ocorrências). Essa metade morta não é inerte: ela duplica cada correção, e faz uma varredura de "o que protege tenant contra tenant?" responder que sim quando a resposta é não.

## O bloqueio real de escala

Cinco itens. Sem eles, um repo novo em outra linguagem, com banco/redis, **não roda** — não "roda pior".

### 1. O repo declara `services`, e a plataforma monta como sidecar nativo *(cinco lentes chegaram aqui)*

**Estado hoje.** No **sandbox** não existe caminho nenhum: `k8s_driver.py:239-305` monta UM container e três emptyDirs (`grep initContainers` = zero); `SandboxProvisionRequest` (`driver.py:26-38`) não tem campo onde um serviço caiba; `sandbox-isolation.yaml:35-46` é default-deny de egress liberando só egress-proxy:8806, model-gateway:4000 e DNS; o egress-proxy fala HTTP/`CONNECT` e libpq/JDBC/redis não falam CONNECT; `readOnlyRootFilesystem: True` + gVisor matam testcontainers. Prova viva: o testbed Java **baixa** testcontainers-postgresql e zonky embedded-postgres e o único teste que roda é `SmokeProbeTest`, "Tests run: 1" (`testbed_java_green_mvnw_test.txt:497-542` vs `:1442-1449`). Qualquer repo cujo `commands.test` toque banco morre em `coder_not_converging` por ausência de substrato.
No **preview**, a resposta é um Postgres para todo mundo: `argocd.py:825` `if kind == "deployable":` é a única condição, 58 linhas com `postgres:16-alpine`, `preview`/`preview` cravados e `POSTGRES_DB` vindo de `config.py:1065 os.environ.get("DSE_PREVIEW_DB_NAME", "fee")` — verificado: **a variável não existe em `infra/` nem `deploy/`**, então produção roda literalmente no nome de banco de um cliente. Repo sem banco paga um pod extra por PR; repo com dois bancos é impossível (o Deployment se chama `postgres`, literal); Redis/MySQL/Mongo não têm caminho (`grep redis services/validation/.../preview/` = zero).

**Desenho mínimo.** UM campo no **topo** do manifesto (não dentro de `preview`), quatro chaves:
```json
"services": [{"name":"db","image":"postgres:16-alpine","port":5432,
              "env":{"POSTGRES_DB":"app","POSTGRES_USER":"app","POSTGRES_PASSWORD":"app"}}]
```
Whitelist fechado (o molde já existe: `parse_repo_preview`, `config.py:490-553`, com `_str`, `_positive_int` com clamp e env estringificado), teto de 3 entradas, `name` em `[a-z0-9-]{1,20}`, `image` com tag obrigatória. **Endereçamento: tudo em `127.0.0.1:<port>`** — sidecar no mesmo pod, sem DNS, sem Service, sem nomes entre serviços.
**Proveniência por consumidor** (é o ponto que a lente errou): o **sandbox** lê do BASE SHA — é gate, e o gate não pode ser reescrito pela própria PR; o **preview** lê do branch da PR, como já faz com `preview` (`argocd.py:722`), senão a PR que adiciona um banco não vê o próprio banco no preview dela.
**Forma do sidecar: nativo** (`initContainers` com `restartPolicy: Always`; a VPS roda k3s v1.31.4, `bootstrap-k3s.sh:10`). ## O que NÃO fazer

Ideias plausíveis que a auditoria rejeitou, com o motivo. Não refaça o debate.

1. **Não aposente marcadores `patched` por regra de idade** ("10 dias", "teto de 72h"). `workflows.py:4153` e `:1043` esperam **sem prazo** — uma PR aprovada e nunca mergeada mantém a execução Running para sempre. O critério é empírico: a execução Running mais velha.
2. **Não troque a escada do Tester por `commands.test` cru.** O ramo npm roda a suíte **escopada aos arquivos do turno** com `--coverage=false` por medida: 400s de suíte completa no testbed Angular, e `collectCoverage:true` com piso global de 80% reprova **qualquer** subconjunto (medido em 9,83%). Rodar o comando do L1 aqui reintroduz custo **e vermelho garantido**.
3. **Não delete `_DEFAULT_SUITE_TIMEOUT_SECONDS`.** É o teto para repo que não declara ou declara absurdo. A receita certa (`min(default, declarado − margem)`) já está prescrita em `config.py:373-376`.
4. **Não deixe o `kind` do preview virar declaração do repo.** `preview_decision` responde "este diff tocou a parte previewável?" — pergunta **por PR**, que declaração de repo não responde. O manifesto declara **como** subir, não **se** há o que subir.
5. **Não unifique o probe do preview em `tcpSocket`.** O `httpGet /` é o que apanhou o dev server Vite respondendo `403 "Blocked request. This host is not allowed."` (`argocd.py:527-533`) — com socket aquele preview teria ficado Ready servindo 403.
6. **Não converta lint/typecheck não-reconhecido em FAIL.** Reexecuta o incidente que `_only_in_changed_files` existe para impedir (dívida herdada vira turno pago que ninguém consegue fechar). O veredito honesto de "não sei" é **ERROR**.
7. **Não vire o SAST para `NOT_CONFIGURED` antes** de o bootstrap emitir `disabled_stages:["sast"]` e isso pousar nos dois testbeds. Invertido, a próxima rc reprova a frota inteira.
8. **Não use `emptyDir: {medium: Memory}` para o banco do sidecar.** É tmpfs cobrado no cgroup de **memória** do Pod — o mesmo `mem_limit` de onde `--max-old-space-size` do Node é derivado a 0,75 (`k8s_driver.py:147-168`, cicatriz `wi_8b083140`, exit 134). Troca despejo por disco por **OOMKill**, que é pior e igualmente mudo.
9. **Não conte com `request=limit` de ephemeral-storage como controle de admissão.** O kubelet calcula allocatable pela **capacidade** do filesystem (29 GB), não pelo espaço livre (6,8 GB): admitiria ~13 sandboxes. Para **memória** funciona (12Gi num nó de 31 GiB → 2), e aí sim o par `512Mi` literal some.
10. **Não chaveie a fairness em `tenant/repo` sem um teto global.** Sozinho, isso multiplica a concorrência por N repos num nó que comporta ~2 sandboxes.
11. **Não apague a "segunda fonte de cap"** (`max_concurrent_work_items`, `0007_wsf.sql:14`): é a coluna que o queue board **exibe** (`app.py:456`, `api.py:154-190`) e a precedência está pinada em `test_fairness.py:104-109`. Unificar significa mudar o painel também.
12. **Não delete `_effective_last_id` do projector.** Não é preocupação de fixture vazada: é cicatriz medida (cursor `audit_log=77704` herdado, drain "convergindo" sem projetar, 2026-08-10), com teste que pina em `test_projector.py:470`. Tire do caminho quente, não do código.
13. **Não trate a credencial de build por repo como remoção.** É troca de eixo com **adição** em dois entregadores (o sandbox hoje não lê Secret nenhuma por work item). O ganho é o eixo, não a contagem de linhas.
14. **Não ache que `forwardAuth` resolve o preview público.** O Middleware é cross-namespace (Traefik recusa sem `allowCrossNamespace`) **e** o problema real é o `cookieDomain`, que o forwardAuth não toca.
15. **Não derive `installation_id` do repo achando que fecha o resíduo do proxy compartilhado.** Header vindo do sandbox não é confiável (`proxy.py:316-322` diz isso por escrito) e `GitHubConfig.is_configured` usa `installation_id` como o gate de "App configurada". É adição líquida, e o modelo de tenant por instalação **já existe** no ingest (`tenant_platform_bindings`).
16. **Não promova o ConfigMap `dse-egress-allowlist` a fonte de verdade.** Ele não tem leitor. A fonte real é `values`; o ConfigMap é o que se apaga.
17. **Não "só chame `create_tenant_audit_partition` no onboarding".** Partição por tenant não ajuda em nada o crescimento — só multiplica objetos e o custo do `max(id)`. E trocar `LIST(tenant_id)` por `RANGE(ts)`, ou dropar o particionamento, é **rewrite** da maior tabela do sistema dentro de uma única transação (`scripts/migrate.py`): decisão de roadmap, não achado de remoção.
18. **Não delete `retention.py` junto com `jobs_scheduler.py`.** O scheduler também dispara a rotação de segredos (ADR-28, `THREAT-MODEL.md:145`).
19. **Não delete `_run_suite` do Tester.** A **porta 5** — a única autoria que sobreviveu à decisão de 2026-08-10 — decide pelo output dele (`activities.py:3369-3437`); `suite_hung(124)`/`resource_kill(137)`/`exec_timeout` **não são deferidos** e são o único relógio que pega hang antes do teto muito maior do L1; e o `npm install` do turno popula o `node_modules` de que o baseline do L1 depende por symlink.
